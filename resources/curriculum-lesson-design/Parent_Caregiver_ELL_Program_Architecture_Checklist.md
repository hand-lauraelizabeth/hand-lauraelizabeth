# Parent & Caregiver ELL Program Architecture Checklist

A planning tool for designing adult English-language-learning programs that connect language development to real-world family, school, community, digital, and institutional navigation.

Created in 2026, this checklist translates methods from Laura Elizabeth Hand's 2020 parent/caregiver ELL work into a reusable program-design framework.

## 1. Define the learner population without overgeneralizing

**Who is the program for?**

**What evidence do we have about learner goals and needs?**

**What is still unknown?**

Check for variation in:

- [ ] English-language proficiency
- [ ] first-language literacy
- [ ] formal education experience
- [ ] digital access
- [ ] digital fluency
- [ ] disability/access needs
- [ ] familiarity with local school/community systems
- [ ] work schedules
- [ ] caregiving schedules
- [ ] transportation
- [ ] confidence/self-advocacy
- [ ] prior experience with adult education

**What information is actually necessary to collect?**

**What information is private/sensitive and should not be collected or broadly shared?**

## 4. Design for three users

### Learner layer

Does the learner-facing material:

- [ ] use clear headings and predictable structure?
- [ ] explain unfamiliar institutional vocabulary?
- [ ] model the task before asking for independent performance?
- [ ] provide enough context to use the material outside class?
- [ ] avoid unnecessary text density?
- [ ] support review after class?
- [ ] use accessible formats?
- [ ] make next steps visible?

### Instructor layer

Does the instructor-facing material include:

- [ ] purpose/rationale?
- [ ] learning objectives?
- [ ] materials?
- [ ] timing or sequence?
- [ ] modeling guidance?
- [ ] comprehension checks?
- [ ] likely misconceptions?
- [ ] mixed-level adaptations?
- [ ] accessibility considerations?
- [ ] optional extensions?
- [ ] what learner evidence to record?
- [ ] what the next instructor needs to know?

### Administrator/program layer

Does the operating structure connect:

- [ ] enrollment?
- [ ] baseline assessment?
- [ ] learner goals?
- [ ] attendance/participation?
- [ ] progress evidence?
- [ ] accessibility/support needs?
- [ ] instructor handoff?
- [ ] reporting requirements?
- [ ] compliance requirements?
- [ ] document retention/privacy rules?
- [ ] program improvement data?

## 5. Integrate digital literacy instead of isolating it

For each digital task, ask:

**What real action is the technology enabling?**

**What device(s) are likely available?**

**Can the learner complete the task on a phone?**

**What happens if internet access is limited?**

**Does the learner need an account/login?**

**What password/privacy risk exists?**

**What is the lowest-tech usable alternative?**

Potential digital competencies:

- browser navigation;
- email;
- forms;
- maps;
- school portals;
- document viewing;
- links/QR codes;
- video calls;
- file upload/download;
- calendar/appointment systems;
- search/evaluation of information.

## 6. Use scaffolded comprehension checks

Move through:

1. **Recognition** — Can the learner identify it?
2. **Selection** — Can the learner choose the correct option?
3. **Explanation** — Can the learner explain what it means?
4. **Guided use** — Can the learner perform with prompts?
5. **Independent use** — Can the learner perform without prompts?
6. **Transfer** — Can the learner perform in a new but related context?

Do not treat silence, confidence, speed, accent, or eye contact as reliable substitutes for comprehension evidence.

## 9. Separate learning evidence from compliance evidence

**Learning evidence** answers: What can the learner now understand or do?

**Compliance/operations evidence** answers: What must the program document for funding, policy, attendance, assessment, or reporting?

Do not collect extra personal information merely because a form can hold it.

## 12. Definition of done

Before launch:

- [ ] Learner need is supported by evidence.
- [ ] Each module connects language to a meaningful action.
- [ ] Learner, instructor, and administrator layers align.
- [ ] Digital skills serve authentic tasks.
- [ ] Mixed-level supports are planned.
- [ ] Accessibility is addressed.
- [ ] Assessment measures the intended competency.
- [ ] Privacy-sensitive data is minimized.
- [ ] Delivery-mode alternatives exist.
- [ ] Instructor handoff is documented.
- [ ] Updating responsibilities are assigned.
- [ ] Third-party and institutional IP is separated from original/public material.
