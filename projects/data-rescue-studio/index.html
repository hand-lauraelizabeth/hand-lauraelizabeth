Data Rescue Studio

Review a CSV or TSV file, see missing values and exact duplicate records, and export a copy. The file is processed locally in this browser; no account is needed.

1. Open a file

CSV uses commas between columns; TSV uses tabs. The file extension determines which separator is used, so tabs within CSV text will not silently become new columns.

3. Inspect rows

4. Reconcile two files

Choose a second CSV/TSV and select the identifier column in each file. Matching is exact and case-sensitive. Repeated keys, missing keys, and unmatched records are not automatically combined. Source positions refer to logical CSV records (header is record 1), not physical text lines when quoted cells span lines. The on-screen findings preview shortens very long values and visibly marks hidden formatting characters; downloaded JSON audits retain exact identifiers.

5. Export original or deduplicated first file

Original input is not changed. Records that differ even slightly are not automatically merged. If a spreadsheet export is blocked after duplicate removal, the reported source record still refers to the original file (header is record 1), not the shorter export.

Spreadsheet-oriented export prefixes potentially dangerous formula-like cells with a tab and includes a UTF-8 byte-order mark for Excel compatibility. Ambiguous line-break formula prefixes, direction controls and unsupported controls block spreadsheet-oriented CSV, with a source record and column message; exact JSON remains available. The tab changes those cell values and is not universally safe across spreadsheet programs. Machine-readable export omits both the tab precaution and byte-order mark. Turn it off for machine-readable CSV and review untrusted data before opening it in spreadsheet software.

For exact decoded cell values and logical source-record positions, export JSON instead. JSON does not add CSV formula prefixes; it is not a byte-for-byte copy or proof of authenticity. For uploaded files, a local SHA-256 fingerprint of the original bytes is included when browser cryptography is available; it can check byte equality, not establish who created the file. If cryptography is unavailable, no fingerprint is claimed. Both downloads contain your data and should be stored privately.

The separate issue index JSON lists original source-record numbers, blank column positions and exact-duplicate links for all findings, not only the visible page. It excludes cell values and header labels, but the filename and optional fingerprint can still be sensitive. It does not identify which duplicates should be deleted.
